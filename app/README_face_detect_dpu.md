# face_detect_dpu 使用与实现说明

单进程版人脸检测 + 识别 + 录入程序（合并显示/检测/识别，DRM 双平面叠层画框）。

---

## 1. 概述

`face_detect_dpu` 在一個进程内完成三件事：

- **显示**：把相机画面送到屏幕（DRM 双平面：VID 视频层 + GFX 叠加层）。
- **检测**：用 DPU 跑 `gate320` 人脸检测模型，逐帧出人脸框。
- **识别 / 录入**：用 ARM CPU 上的 `mobilefacenet.onnx` 提取特征，与已录入的 gallery 比对（识别），或把新人写入 gallery（录入）。

代码版本标识：`[DBG-VER] face_detect_dpu MERGE_GFX`（单进程：双路同流 + GFX 叠层画框）。

---

## 2. 硬件 / 显示架构

- **video0（/dev/video0）**：1080×1080 主画面，送 **VID 平面（默认 ID 39，下层视频）** 显示。
  - 支持零拷贝（设置 `VID_ZC` 时，DP dumb buffer 经 dmabuf 直接给 V4L2）。
- **video1（/dev/video1）**：320×320 检测流，跑 DPU 检测。**与 video0 同一视图（同一镜头/同步双摄同视角）**。
- **GFX 平面（默认 ID 40，上层叠加）**：在 video0 画面上叠框，逐像素 alpha 透出视频。
  - **绿框**：检测/识别到的人脸框（`(0,255,0)`）。
  - **白框**：录入目标区（仅录入模式显示），提示"把脸放到这儿"。

> 注意：白框和判定用的 `in_roi` 是**同一套 CAM0（1080）坐标系**，两者对齐。

## 4. 运行命令

### 显示 + 检测 + 识别（不录入）

```sh
face_detect_dpu /usr/share/vart/face_detector/gate320.xmodel /dev/video1
```

### 录入新人（交互式）

```sh
face_detect_dpu --enroll Zhang_San /usr/share/vart/face_detector/gate320.xmodel /dev/video1
```

流程：启动后屏幕出现**白色目标框** → 把正脸移入白框中央 → **按 Enter** 开始采集 → 满足判定后 `采集中 1/5 … 5/5` → `已录入`；输入 `q` 取消。
（非交互 / stdout 被重定向时自动开始，兼容无人值守脚本。）

### 临时覆盖参数（无需重编）

```sh
FACE_THR=0.40 ENROLL_THR=0.55 REC_SIM=0.5 \
  face_detect_dpu --enroll Zhang_San /usr/share/vart/face_detector/gate320.xmodel /dev/video1
```

---

## 5. 识别流程（每帧）

1. DPU 检测得到当帧最佳人脸 `best`（原始检测，不受去抖影响）。
2. 若 `best.score >= FACE_THR`（默认 0.40），调用识别：
   - 用 5 关键点（若有）做仿射对齐到 112×112，否则用检测框中心裁剪；
   - `mobilefacenet` 前向得到 512 维 embedding，L2 归一化；
   - 与 gallery 中每个人做余弦相似度，取最大值 `best_sim`。
3. 若 `best_sim >= REC_SIM`（默认 0.40）则输出姓名，否则 `Unknown`。
4. **输出节流**：仅当识别到的标签变化时才打印 `[rec] 识别到: <name> (sim=..)`；人脸真正丢失后清空，下次重现会再播报（计算每帧都在做，只是不刷屏）。

---

## 6. 录入流程（判定链）

`--enroll` 按 Enter 开始（arming）后，每帧依次过以下闸门，任一道不过则提示并清零累计，不写盘：

```
分数 >= ENROLL_THR(0.55) 且 框有效(x2>x1) ?
  └─ 否 → 不计（等下一帧）
  └─ 是 → 算人脸中心(cx,cy)与框宽(bw)，均在 1080 坐标系
        ├─ 尺寸合理？  bw ∈ [0.12, 0.70] × 1080
        ├─ 关键点合理？（模型有关键点时）5 点均落在检测框内（误检框关键点乱飞→淘汰）
        └─ 中心在白框内？  cx,cy ∈ 白框矩形（中央 30%，即 378..702）
              └─ 全过 → 累计：中心漂移过大(换脸/大移动)则复位；满 5 帧 → 平均 embedding → 写库
```

- 平均后的 embedding 追加写入 `REC_GALLERY`（默认 `/root/tmp/face_rec/gallery.txt`），并加入内存库，**录入后立即可被识别**。
- 录入必须依赖识别模型 `mobilefacenet.onnx`；缺失时打印错误并退回检测模式。

## 7. 原理详解

### 7.1 显示：DRM 双平面硬件合成
- 两块 DRM plane：`VID(39)` 在下、`GFX(40)` 在上（本板 plane ID 大者叠在上层，实测 40 正常盖在 39 之上）。显示控制器硬件把两层合成输出到 CRTC/屏幕，无需 CPU 参与混合。
- VID 层：`video0` 的 1080×1080 RGB888 帧铺满缓冲左半，再被 `SetPlane` 拉伸映射到全屏 1920×1080；右半无视频内容为黑。
- GFX 层：ARGB8888 叠加层，整帧先 `memset` 透明（alpha=0），只在需要处画框（alpha=255）。通过 `set_plane_prop(gfx,"g_alpha_en",0)` **关闭全局 alpha、启用逐像素 alpha**，于是框外透出视频、框内不透明。
- 防撕裂：NBUF_FB 个 dumb buffer 轮转，持有"正在显示"的缓冲直到被下一帧替换，新帧才上平面。
- 零拷贝（`VID_ZC`）：把 video0 的 V4L2 缓冲导出 dmabuf fd，交由 DP 分配 dumb buffer 作为导入目标，省去 CPU `memcpy`；否则走 `memcpy` 把 video0 拷入 VID dumb buffer。

### 7.2 双路相机与坐标空间
- `video1` 固定 320×320 先 `STREAMON`（锁时序），`video0` 随后开流；二者**同一视图**。video1 帧送 DPU 检测，video0 帧送显示（并拷贝 BGR 给识别）。
- 检测在 320 空间，显示/判定在 1080 空间，靠比例 `sc = 1080/320` 把检测框坐标乘以 sc 还原到 1080 显示坐标；白框 `in_roi` 判定也在同一 1080 坐标，所以画面与判定天然对齐。

### 7.3 检测：DPU 网格化单阶段检测器（gate320）
- 输出特征图 Hd×Wd，每格（anchor-free）预测 1 个候选：`score + 4 框偏移 + 10 关键点`（共 15 通道；无关键点模型为 5 通道）。
- 对每格做 `sigmoid(score)`，≥`CONF(0.05)` 才保留；用 `stride` 把网格中心还原到 320 原图坐标，得检测框 `(x1,y1,x2,y2)` 与关键点。
- 取**全局最高分** `best` 作为当前帧人脸（无显式 NMS，靠网格单候选 + 取 max）；`score` 即"是人脸"的置信度（0~1）。

### 7.4 识别：mobilefacenet + 余弦相似度
- **对齐**：优先用 5 关键点做 similarity transform——把检测到的 5 点（按 y 排序取眼/鼻/嘴，再按 x 排序区分左右）仿射对齐到标准模板 `ref(112×112)`（`estimateAffinePartial2D` + `warpAffine`）；无关键点则用检测框中心裁剪到 112×112。
- **预处理**：`(img-127.5)/128`，BGR→RGB。
- **前向**：mobilefacenet 输出 512 维特征，L2 归一化到单位球面。
- **比对**：与 gallery 每个 embedding 算余弦相似度（已归一化即点积），取最大值 `best_sim`；`≥ REC_SIM` 判为该人，否则 `Unknown`。
- **余弦相似度的意义**：同人向量夹角小（通常 0.7+），不同人接近随机（约 0.4）。输出做了节流——仅标签变化才打印，避免每帧刷屏（计算仍每帧执行）。

### 7.5 录入：多帧平均 embedding
- 同人不同帧/姿态的 embedding **向量平均**（平均后归一化），抑制单帧噪声与姿态抖动，提高后续识别鲁棒性。
- 写入 `gallery.txt` 格式：`姓名 f1 f2 … f512`（空格分隔），下次启动 `load_gallery` 读回。
- **五道防误录闸**（全过才累计写盘）：① 分数 `≥ENROLL_THR(0.55)` 滤低分噪声；② 框宽 `∈[0.12,0.70]×1080` 滤太远/异常；③（模型有关键点时）`lmk_in_box` 要求 5 关键点都落在检测框内——误检框关键点常乱飞到框外；④ 中心 `in_roi` 落在白框（中央 30%）内，保证对准；⑤ 中心漂移容限，换脸/大幅移动即复位。满 5 帧才平均写库。
- 取 5 帧而非 1 帧：平滑瞬时抖动。

### 7.6 去抖与平滑
- **迟滞去抖**（`DET_OFF=0` 时）：连续 `N_DET(1)` 帧有脸才确认"出现"，连续 `N_LOST(5)` 帧无脸才确认"消失"，避免框闪烁/闪现。
- **绿框时间平滑**：EMA `sm = a·new + (1-a)·sm`（`a=DET_SMOOTH=0.35`）并加每帧限幅，防止误检远跳导致框瞬移/拖影；人脸完全消失后 `sm_init` 复位避免残影。

### 7.7 阈值设定的依据
- `FACE_THR(0.40)`：检测器原始置信门槛，同时是"跑不跑识别"的开关（低于它不浪费 CPU 跑 mobilefacenet）。
- `ENROLL_THR(0.55)`：基于实测分值分布——背景噪声最高约 0.45、真实人脸一般 ≥0.60，取中点 0.55，使噪声必被挡、真脸必过。
- `REC_SIM(0.40)`：余弦相似度决策线；调高减少误认陌生人，调低更易认出（同人通常 0.7+，陌生人约 0.4）。

## 8. 全部可配置参数

### 命令行

```
显示+识别 : face_detect_dpu <模型(.xmodel或目录)> [相机(默认/dev/video1)] [检测阈值]
录入人脸 : face_detect_dpu --enroll <姓名> <模型> [相机]
```
> 非录入模式的第 3 个位置参数 = `FACE_THR`（环境变量优先于位置参数）。

### 环境变量（均可不重编覆盖；启动"配置"区打印生效值）

| 变量 | 默认 | 说明 |
|------|------|------|
| `FACE_THR` | `0.40` | 检测/绿框门槛；分数≥它才算"有人脸"，也决定要不要跑识别 |
| `ENROLL_THR` | `0.55` | 录入分数门槛（背景噪声≤0.45、真实人脸≥0.60，取中间值） |
| `REC_SIM` | `0.40` | 识别余弦相似度决策阈值；≥它才认出某人，否则 `Unknown`（调高更严） |
| `DET_OFF` | 未设置 | 去抖开关：设置=关（每帧直接判定），未设置=开（连续 N 帧确认） |
| `DET_NDET` | `1` | 去抖开时，连续多少帧有脸才确认"出现" |
| `DET_NLOST` | `5` | 去抖开时，连续多少帧无脸才确认"消失" |
| `DET_SMOOTH` | `0.35` | 绿框时间平滑(EMA)系数；`0`=关平滑（画原始抖动框） |
| `REC_MODEL` | `/root/tmp/face_rec/deploy/mobilefacenet.onnx` | 识别模型(.onnx) |
| `REC_GALLERY` | `/root/tmp/face_rec/gallery.txt` | 已知人库（录入时追加写） |
| `VID_PLANE` | `39` | 下层视频 DRM 平面 ID（叠放顺序异常时覆盖） |
| `GFX_PLANE` | `40` | 上层叠加 / 画框 DRM 平面 ID |
| `VID_ZC` | 未设置 | 设置即启用 video0 零拷贝(dumb→dmabuf) |
| `DBG` | 未设置 | 设置即打印每帧识别细节(sim / feat_norm) |

## 9. 已修复 / 设计要点

1. **误录（噪声被录入）**
   - 原 `ENROLL_THR` 默认 `0.60` 高于真实人脸分（真脸一般 ≥0.60、但边界帧更低），反而把偶尔冲高的背景噪声录了进去。
   - 改为默认 `0.55`（落在噪声≤0.45 与真脸≥0.60 之间）；并新增**框尺寸合理性** + **关键点几何校验**两道闸，真正拦住非人脸。
2. **启动即自动录入**
   - 改为交互式：显示白框 → 对准后按 Enter 才开始累计（非交互模式仍自动开始）。
3. **"绿框"其实是黄色**
   - 原配色 `R=255,G=255,B=0` 为黄色，已改为真正的绿色 `(0,255,0)`。
4. **白框只在录入模式显示**
   - 白框是录入目标区引导 + `in_roi` 闸门；纯检测模式不画（符合预期）。
5. **识别/检测相机同一视图**
   - video0（显示）与 video1（检测）同视角，白框坐标与判定坐标直接对齐，无需换算。

## 10. 常见问题

- **绿框/白框不显示**：确认 GFX 平面在 VID 之上（默认 40 在上），且启动日志 `GFX g_alpha_en -> 0 : ok`。框颜色：绿=人脸，白=录入目标区（仅录入模式）。
- **录进去的不是我**：先删库重录——`rm -f /root/tmp/face_rec/gallery.txt`，再按第 4 节交互录入，确保脸在白框中央、且终端出现 `采集中 5/5` 后才算成功。
- **识别太松/太严**：调 `REC_SIM`（高=严、低=松，同人通常 0.7+，陌生人约 0.4）。
- **平面顺序异常（框被视频盖住）**：用 `VID_PLANE` / `GFX_PLANE` 覆盖平面 ID。
